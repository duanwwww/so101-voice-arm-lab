# 100 条指令怎样构造、计分和复核

这套数据检验一个问题：给定操作者的话和控制端实际可提供的场景摘要，规划器能否生成语义正确的控制 JSON？100 条均为本轮逐条撰写的合成输入，Codex 辅助拟定场景和预期结果；尚无课程小组成员独立盲审。参考结果在获得模型回复前冻结。冻结后的 SHA-256 为 `79d77367c2f22e61fc943b1b09e8ca120f1ab03ee6529be84c915e314bcdd9c3`。[输入、场景与参考答案](../configs/planner100.json)

| 分组 | 预期动作 JSON | 预期模型追问 JSON | 预期本地处理 | 总计 |
| --- | ---: | ---: | ---: | ---: |
| 开发，用于分析错误与改写提示词 | 28 | 8 | 4 | 40 |
| 留出，用于检验冻结的提示词 | 42 | 12 | 6 | 60 |
| 合计 | 70 | 20 | 10 | 100 |

**报告正确控制 JSON 时，先看留出的 42 条动作题。** 54 是留出组需要规划器回复的总数，包含 12 条应该追问的输入。60 是加上 6 条本地处理后的整条软件链路分母。全库对应的三个分母分别为 70、90 和 100。如果网关限流或两版取得的回复数不同，还需列出每版覆盖率、未完成数以及双侧取得回复的共同样本数。将两版回复相加不能增加独立输入数。

## 任务覆盖

100 个输入文本唯一，开发与留出按表达或任务族分组，68 个族名没有跨组重复。相同基础技能在两组都出现。例如中文数字、阿拉伯数字和繁体表述都可请求平移。13 条含两至四步，8 条依赖上一轮追问；根据 70 份动作参考 JSON 原样计数，共 88 个动作条目，包括平移 30 次、工位搬运 20 次、转腕 10 次、放置 9 次、抓取 8 次、观察 6 次、归位 5 次。等价地展开一条搬运会得到两个动作，报告中沿用原始条目数。[动作定义与校验](../arm_lab/planner.py)

场景摘要中，A/B/C 各有唯一红块的输入分别占 23/19/22 条，空桌占 21 条，夹爪已持物占 13 条。双候选与单块工位外各只有 1 条。输入含 3 条手工注入的物名或颜色同音错字。计数反映本轮特意挑选的课程场景，不能代表自然说话频率、教室语音识别准确率，或复杂背景下的视觉可靠性。规划器取到的工位和 XY 是给定的场景输入；OpenCV 的精度要另用图像与标注测量。

下面三个例子都来自开发集。

| 编号 | 指令与场景 | 参考与解释 |
| --- | --- | --- |
| P016 | “请把手腕往下转十五度。”空爪，红块在 A。 | `{"steps":[{"action":"wrist","deg":15}]}`。在本机约定中向下为正，15 度恰好可用。写成 −15 会把方向反过来。 |
| P024 | 画面中只有 A 的红块。上一句是“请把红块搬走。”系统问“请问送到哪个工位？”，这句回复“目的地选右侧的工位。” | `{"steps":[{"action":"transfer","object":"red_1","from":"A","to":"B"}]}`。同一起点、终点的相邻抓取和放置也可通过语义比较。 |
| P033 | “去 A 区抓那块红积木。”画面只在 C 检到木块。 | 参考为 `{"action":"ask","question":"画面只在 C 看到木块，请核对抓取起点。"}`。改从 C 抓会忽略操作者明确说出的起点。 |

## 金标与评分会漏掉什么

- **动作等价。** 严格 JSON 对照忽略对象键顺序、空格和等值数的书写差异。语义评价还允许同物体、同起讫的搬运与相邻“抓取＋放置”等价，但保留独立的观察、转腕、归位、单位和动作顺序。提出动作的准确率与控制器最后是否放行分别计。
- **追问内容。** 20 道模型追问题各有预先登记的关键词组；各组至少命中一个同义词即通过焦点检查。对 P033 离线代入“画面的曝光正常吗？”会因“画面”而误判为命中；代入“A 格里没有这个方块，改从另一个格子取可以吗？”能指出冲突，却因用词不同未命中。这两个例子是构造的评分器测试文本。解读模型成绩时应查看 `ask_type_correct` 和原始问句，人工复核追问内容。严格逐字相同对追问尤其苛刻。
- **明示坐标与可达性。** 所有动作参考 JSON 已逐条通过现有动作解码、场景状态和数值范围校验，100 条的本地／规划分流亦与预期相符。这两项检查只验证参考能被软件理解。本数据库没有为每道题模拟机械臂轨迹或测量物理落点，动作 JSON 答对也不代表真实执行成功。
- **文本无法独立判定的情形。** 操作者说“不要暂停”属于忽略这句禁止指令；说“恢复控制”能请求恢复，真正能否解锁由控制器当时的暂停或故障状态决定。用例对这类输入只标注分流意图。其余口语默认采用工程已有的工位约定，现场未标定底座和摄像头时不宜套用。
- **泛化范围。** 族名分组减少直接复用同一句和模板的机会；三个工位、七类动作和合法轴向仍为两组共有。语义分数只能说明在本题集上的表现。本轮留出不是由外部团队保存的隐藏考卷。

## 两版提示词会看到什么

对原版和首个候选版分别在离线内存中构造 90 个可规划输入的请求体。对每个输入，单独将副本中的 `id`、`split`、`family`、`route`、`expected` 和 `ask_focus` 替换为哨兵值，再构造请求体。两版各 90 份均与替换前完全相同。用户消息只有 `command`、`objects`、可选 `holding` 和 `dialogue`；物体包含可见物体编号、工位与可选平面坐标。对话只含上轮指令和系统已问过的问题。系统消息是同一版本共用的提示词，含通用 JSON 例子、工位和轴向规则。本地处理的 10 条不送模型。此项检查不需要凭据、不发网络请求，也未读取留出集的预测答案。[实际请求的组装](../arm_lab/model_access.py) · [调度、提前冻结与题目选择](../scripts/evaluate_planner100.py)

## Windows 离线复核

在工程根目录执行。第一行会用本地规则生成新的离线基线，第二行验证评分器。第三行核对冻结文件的字节哈希。在线模型成绩需要另行取得真实回复，规则基线与参考自检均不计入模型成绩。

~~~powershell
uv run --frozen --extra voice --extra data python -m scripts.evaluate_planner100 local
uv run --frozen --extra voice --extra data python -m unittest discover -s tests -p test_planner_scoring.py
Get-FileHash -Algorithm SHA256 configs/planner100.json
~~~

### 用相机和物理状态重放

预先选定 12 条留出输入 P042、P045、P048、P053、P059、P065、P066、P070、P072、P083、P085、P090，其中 9 条动作、3 条追问。场景覆盖 A/B/C 和空桌，含单抓、两次搬运、正负向平移及转腕。每次从 OpenCV 实际读取当前帧，要求真实检测到的工位、夹持状态及平面坐标与参考场景相符（二维欧氏位置误差 ≤2 mm）。仿真独立核对双指接触、抬升超过 20 mm、三帧放置落位、末端位置及腕角。追问须保留原关节和仿真时间，且问句涉及预设的缺项。本项验证仿真运动与回执的对应关系。[重放脚本与固定名单](../scripts/replay_planner100_sim.py)

以下命令只读取冻结输入和本地保存的回复，均不调用模型。第一行用参考答案作测试替身，在单独的输出目录检查重放器；第二行示范读取指定版本的留出原始回复，版本名须取本轮已冻结的名称。缺失回复会单列。

~~~powershell
uv run --frozen --extra voice --extra data python -m scripts.replay_planner100_sim --fixture
uv run --frozen --extra voice --extra data python -m scripts.replay_planner100_sim --version candidate
~~~
