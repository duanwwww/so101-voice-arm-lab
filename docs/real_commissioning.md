# 把仿真控制接到课程 SO-101 前

本次只读核对了课程程序、LeRobot 0.6.1 发布包和第三方 SO-101 轨迹。没有打开串口、读现物寄存器或下发动作。现场从臂的具体型号、夹爪零位、设备地址、夹持力与相机配置仍由现场核对。

| 现场关心的问题 | 现有课程链路能提供的证据 |
| --- | --- |
| 哪些关节真的有读数？ | 入场读总线 Present_Position 并核对中位，随后读六轴位置。前五轴用角度，夹爪用校准行程的 0–100，课程数学模型再换算成近似关节角。末端坐标来自正运动学计算。课程入口未配置腕部相机。课程入口及读位置（另领课件 so101_lab_new/control.py） · 模型与行程换算（另领课件 so101_lab_new/so101_core.py） |
| 能发哪些指令？ | 课程设定持久的位置目标，约每 20 ms 计算限速后的下一目标，调用 send_action 写各关节 Goal_Position。启动时先把目标设到当前读数，再 configure。LeRobot 的 configure 对电机设置 POSITION 模式，并给夹爪配置最大扭矩限制、保护电流及过载扭矩寄存器。课程例程自身还检查跟随偏差和无进展超时，硬件异常与软件 TrackingError 要分别记录。课程依赖锁定版本（另领课件 so101_lab_new/requirements.txt） · [LeRobot 0.6.1 驱动](https://github.com/huggingface/lerobot/blob/v0.6.1/src/lerobot/robots/so_follower/so_follower.py#L159-L229) |
| 电流、负载、故障、力控呢？ | 匹配的 Feetech 寄存器表列有 Present_Load、Present_Current、Status、Moving、Present_Temperature 等。课程的观测循环只读位置，没有把这些寄存器或双侧接触信号送入抓取决策。配置过载保护不会产生一对指尖接触测量值。仿真里的指尖接触、离桌状态、以 N·m 表示的执行器上限无法与现有 position 接口直接等价。即使现场读得到电流，也需要核对型号、单位、更新率并区分空爪、夹住与卡死。[固定版本寄存器表](https://github.com/huggingface/lerobot/blob/v0.6.1/src/lerobot/motors/feetech/tables.py#L75-L91) · [仿真夹爪反馈结构](../arm_lab/gripper.py) |
| 停止意味着什么？ | 夹爪命令与实测相差超过行程的 20% 会触发课程的软件保护，超过 5% 且默认 3 秒没有有效进展也会停止。闲时仍可能持续追上一个目标。课程退出会尝试用当前实测位置覆盖旧目标，然后等现场确认托稳后才卸力。通信丢失时这次覆盖也可能失败。实际报警原因应保留当时错误、关节读数与时刻。课程停止与托稳约定（另领课件 so101_lab_new/README.md） · 控制器实现（另领课件 so101_lab_new/control.py） |

如果现场确认是飞特 STS3215 对应规格，厂商说明重新发位置目标可能清除过载或过流保护标志。课程退出时的“尽力保持当前位置”和“遇到故障锁存”的处置应分别设计：发现硬件报警或故障来源不明确时，先保留故障、让现场人员支撑和按设备约定处理，禁止自动重发旧目标或自行复位。[飞特 STS3215 产品规格书第 5 页](https://www.feetechrc.com/Data/feetechrc/upload/file/20200611/6372749961523760249976542.pdf)

## 用真实位置记录试了一个容易误判的规则

对公开 SO-101 的单海绵抓放两组数据，离线读取真实动作和实测夹爪位置。这两个通道都没有独立的接触编码。每回合搜索连续 15 帧（30 Hz），要求实测开度落在固定摆位组定义的低位、整窗实测极差 ≤0.5，且每帧命令与读数差 ≤1.0。数值沿用数据原生单位，低位约 10.22；这些阈值只用于检验这个假设，不可下发到实机。

| 公共记录 | 有“低、稳、跟得上”窗口 | 首个窗口从第 0 帧开始 | 能由该位置通道独立证明双指接触并举起 |
| --- | ---: | ---: | ---: |
| 固定摆位 64 回合 / 30,160 帧 | 64/64 | 63/64 | 0 回合具备这组测量 |
| 随机摆位 64 回合 / 44,727 帧 | 64/64 | 60/64 | 0 回合具备这组测量 |

如果把这个窗口直接当作“刚抓住”，123/128 个回合一开场就会满足。只比较开度或跟随偏差，无法确定在哪一步发生了抓取。本次只审查轨迹数值，128 段在这个证据口径下均为“未确认”。实际物体是否抓住仍需独立画面、接触传感或人工标注。固定与随机组分别核对了原始 Parquet 哈希。[逐回合首窗口和数据哈希](../results/safety/real_jaw_evidence.json) · [真实数据的发布者](https://huggingface.co/datasets/aswinkumar99/LeRobot-SO101-Pick-Place)

已有缓存时可独立重跑。新电脑先依照工程 README 的 evaluate-real 命令准备公开数据。

## 预约按这个顺序核对

1. 现场核对型号、行程、轴方向、校准文件、紧固、净空和立刻停机的手段。确定两个相机各自的设备编号和可见区域，腕部无实物摄像头时只用固定视角。
2. 先记录静止和空爪小幅度运动时的位置、命令和时间。区分“读回确实更新”和“进程重复使用旧样本”。如果要增加电流、负载或错误状态读数，先验证实际驱动、单位和异常表现，保留原有保护。
3. 支撑条件和边界得到现场确认后，用指定测试物体验证“接近、接触后终止继续闭合、可控试抬、能保持、受控释放”。要用独立画面或传感证明物体随爪移动。只看到夹爪不动、持续大偏差、无回读或驱动报警都要中止任务，保留状态，避免用重复发目标覆盖故障。
4. 现有课程接口无法直接给出已验证的受限握持力。若不能在这台从臂实现并验证持握方式与安全处置，现场只做空爪示教、限域微调和视觉确认，抓放继续用仿真展示。使用先前仿真的力矩数值替换驱动寄存器的单位会给出错误的控制量。
5. 在 15 回合登记表记录动作回执，配合前后画面、独立刻度和现场观察写实际落点或位移。只有确实完成了现场记录的项计入实机成绩。[双视角记录](field_cameras.md) · [现场登记表](../results/safety/field_trials_blank.csv)
