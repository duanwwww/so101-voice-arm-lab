# OpenCV 如何影响机械臂指令

实拍中有 95/100 张至少有一个框匹配红木块，但只有 67/100 张能唯一、正确地指出它。在此前未用于项目的 264 张外部仿真图中，有 77 张没有标注红块，其中 57 张仍然只报出了一个候选。对于“把红块搬到 B”的指令，只凭“检测到一个红色区域”不足以证明它就是木块。[逐帧真值、检测框及双视角结果](../results/safety/vision100.json)

## 有发布者标注的两套图像

用文末命令可在本机重绘四张对照图，依次为正常命中、机械臂区域过检、边界覆盖不足和苹果误检。绿色实线是发布者的标注，粉色虚线是 OpenCV 的预测。仓库保留逐帧文件名、图像哈希和框坐标，原图由发布者提供，数据卡未声明图像再发布许可。[图像与标注来源](https://huggingface.co/datasets/pengxianglu/vigiclaw-yolo-dataset/blob/e2e9acfbfdf827776c06673ee4103c970ac0d29b/README.md) · [逐帧结果](../results/safety/vision100.json)

使用 VigiClaw 同一固定版本的两个子集。发布者的全部实拍图刚好 100 张，只有 train 划分，项目已在前期用过。本次重新读取全部原始图像与标注，并额外检验此前未用的全部 264 张外部仿真图。实拍标签为矩形框，仿真标签为物体轮廓，按包含像素端点的外接矩形评估。两个子集各自查找 red cube 类别。读取时逐一核验图像、标注清单和类别文件的发布者哈希与图像尺寸。标注在产生预测以后才进入计分。[发布者固定版本与数据说明](https://huggingface.co/datasets/pengxianglu/vigiclaw-yolo-dataset/tree/e2e9acfbfdf827776c06673ee4103c970ac0d29b)

每张图至多标注一个红块。对原始 RGB 整图运行项目的 HSV 阈值与连通域程序；没有外部桌面工位标定，传入空的工位表。最大交并比 IoU ≥ 0.5 记一次真阳性，此图的额外框全部记假阳性；无标签仍出框也记假阳性。表中“唯一错”含单框但位置匹配不足，以及无目标却报单框。公开集没有本项目桌面毫米坐标，不能从这些实拍框推导真机定位精度。[实际检测实现](../arm_lab/vision.py) · [评测及独立计分代码](../scripts/evaluate_vision100.py)

实拍的 187 个假阳性中有 182 个集中在后段 41 帧，该段只有 11 帧唯一正确。实拍唯一判错的一帧仍框到了目标附近，但 IoU 只有 0.49164，低于预定阈值。外部仿真里的错误更直接，例如没有红块的一帧，唯一预测框和发布者标注的苹果框匹配。所有 68 个错误单框逐个与非目标标签比对，49 个与苹果标签匹配，11 个与红碗匹配，5 个与红盘匹配（各按 IoU ≥ 0.5 计）。这三类物体本身就可能满足红色阈值。复用此前在实拍开发帧选出的面积和长宽比过滤，264 张中 TP、FP、FN 和错误单框数均无改善。后续宜在固定台面限定可操作区域，并检验已知尺寸或其他独立视觉证据对这 57 张无红块误报的作用。[实拍边界样本](https://huggingface.co/datasets/pengxianglu/vigiclaw-yolo-dataset/blob/e2e9acfbfdf827776c06673ee4103c970ac0d29b/real/images/image_20260515_223457_927.jpg) · [仿真苹果误判样本](https://huggingface.co/datasets/pengxianglu/vigiclaw-yolo-dataset/blob/e2e9acfbfdf827776c06673ee4103c970ac0d29b/sim/images/d1_base_camera_rgb_20260414_102823.png)

## 本组新生成的 100 个双视角摆位

采用种子 20261126，每类场景 10 个，不同位置、绕竖轴转角和工位。每次摆好桌面后分别读取生产入口的固定与腕部画面，然后读取 MuJoCo 中物块中心和旋转后的包围范围作为独立真值。木块必须完整落在相应工位内；有第二个同色候选时应停止选择。固定、腕部均处于待机姿态。低曝光、极暗两组只调整固定相机曝光，腕部保留正常曝光。实验没有发送运动指令。

| 每行 10 个摆位 | 固定相机正确报告工位 | 腕部相机正确报告工位 |
| --- | ---: | ---: |
| 正常 / 固定相机低曝光 / 固定相机极暗 | 10 / 10 / 0 | 10 / 10 / 10 |
| 工位边缘 / 距中心约 6.5–10 mm | 2 / 10 | 0 / 10 |
| 蓝色干扰 / 第二个红色候选 | 10 / 0 | 10 / 0 |
| 固定相机遮挡 / 红块表面反光条 / 目标移出工作区 | 0 / 0 / 0 | 6 / 0 / 0 |

100 个摆位中有 72 个包含唯一且完整处于工位的目标。固定相机正确指认其中 42 个，腕部正确指认 56 个，两机均未报错工位。剩余场景各自保留为未确认。固定相机确认正确的 42 个样本中，台面 XY 中心误差中位 0.828 mm、P95 为 1.897 mm、最大 2.006 mm，这些毫米值只适用于当前仿真标定和相机姿态。

**8 mm 抓取半径处出现了两次准入错误。** 依据物理位置及目标唯一性，有 63 个样本满足 8 mm 条件。用视觉估计值执行相同的半径判断，正确放行 33 个，另误放行 2 个。B 工位样本 offset-03 的真实偏差 8.92 mm，估计为 7.06 mm；offset-06 真实偏差 9.37 mm，估计为 7.87 mm。两例工位名称都判断正确。此处只测试抓取前的位置门槛，实际下爪成败需要运动实验。

对这批数据离线重算，把视觉阈值从 8 mm 收到 7 mm，物理合格标准仍为 8 mm，正确放行从 33 变成 31，错误放行从 2 变成 0。6 mm 在这批样本上也为 31 和 0。这是看过误差后的敏感性分析。

随后固定 7 mm 为唯一候选，在独立的新摆位上与原值再比一次，期间没有调整参数。新种子为 20261127，三个工位分别沿八个随机扰动的方向摆放，预定半径为 6.5、7.3、7.8、8.2、8.7、9.5 mm，转角另行抽样。144 个近边界样本中，固定相机配 8 mm 视觉门槛误放 **15/72** 个物理越界样本，正确放行 **56/72** 个物理合格样本；改用 7 mm 后，这两项变为 **2/72** 和 **26/72**。上一批的零误放没有复现。就课程演示而言，把木块摆在工位中心附近有利于避开这段易混淆区域；若要扩大抓取范围，下一步应独立标定相机、验证边缘位置误差，再决定准入余量。生产阈值保持原值。[逐摆位真值、两机输出、两次半径对照](../results/safety/vision100.json)

## Windows 下复现

工程目录中首次加 `--download` 拉取固定版本的外部数据。之后可断网复跑，仍会逐文件验哈希。下面命令会重算检测和指标，无需使用模型或连接机械臂。

~~~powershell
uv run --frozen --extra voice --extra data python -m scripts.evaluate_vision100 --download
uv run --frozen --extra voice --extra data python -m scripts.evaluate_vision100
uv run --frozen --extra voice --extra data python -m unittest discover -s tests -p test_vision100.py
~~~

完成上述下载后，以下命令在本机生成对照图。脚本逐一检查原图 SHA-256，从既有结果取框。

~~~powershell
uv run --frozen --extra voice --extra data --with pillow python -m scripts.evaluate_vision100 --examples results/safety/vision100_examples.png
~~~
