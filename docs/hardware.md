# 真机接入与现场验证

本文用于预约设备前的准备及现场验收。**当前 `run`、`serve` 均执行 MuJoCo 仿真，尚无本项目的真机完整链路成绩。** 仓库已提供摄像头取证、现场记录表和计分工具；串口执行器、真实图像到机械臂坐标的转换、设备端故障处置仍需实现。[项目入口](../README.md) · [系统设计](workflow.md) · [现有实验](experiments.md)

## 1. 接入前需要完成的适配

| 接入项 | 当前实现 | 真机接入工作 |
| --- | --- | --- |
| 设备与驱动 | 本仓库依赖用于仿真、语音和评测；未安装真机驱动。 | 核对从臂型号、供电、USB 控制板、COM 端口及实验室提供的驱动版本。确认设备确为与模型匹配的 SO-101，取得这台设备的校准 ID 和文件。当前网页启动参数 `--port` 是 HTTP 端口，不是机械臂串口。 |
| 动作执行 | [命令入口](../arm_lab/__main__.py)和[网页接口](../arm_lab/web.py)构造 `Simulator`；动作由[执行流程](../arm_lab/flow.py)分段完成。 | 接入独占串口的执行器，实现状态读取、限速运动、夹爪控制、停止及故障回执。逐项对应原执行接口，先记录拟发送目标，再接通实际写入。当前没有可直接切换真机的配置开关。 |
| 运动学与单位 | [公开版 IK](../arm_lab/kinematics.py)依据仿真模型求解；命令 JSON 平移使用 mm，转腕使用 °。 | 标定实际夹持中心 TCP、关节顺序、零位、正方向和限位。核对驱动读写单位，明确 mm/m、度/弧度及夹爪行程之间的转换。课程现有控制程序应与本项目适配器分别验收。 |
| 图像与工位 | 网页画面来自仿真；[固定相机投影](../arm_lab/vision.py)和[腕部投影](../arm_lab/wrist_view.py)使用仿真相机参数。 | 为控制链接入 USB 图像源、采集时间和标定参数，导入实际工位边界、台面高度及木块尺寸。OpenCV 摄像头通常输出 BGR，当前检测函数接收 RGB，接入时需明确转换。取证工具能够采图不等于控制链已消费真实图像。 |
| 路径与障碍 | [运动预检](../arm_lab/motion_guard.py)检查仿真限位、净空、载物包络和登记障碍。 | 示教接近、抓取、试抬、搬运、放置及撤离姿态；实测桌面、支架、线缆等障碍。障碍配置使用底座坐标系、米单位的轴对齐包围盒，字段见[配置示例](../configs/keepouts.example.json)。示例坐标及仿真余量不能直接用作实机参数。 |
| 夹爪与故障处置 | [夹爪逻辑](../arm_lab/gripper.py)使用仿真双侧接触、开度和离桌反馈。 | 核对驱动实际提供的位置、负载、电流及报警字段、单位和刷新率；以现场证据设计接触判定和持握策略。检测到接触、异常停滞或报警后停止继续收紧，禁止自动重发闭合目标或自行清除故障。 |
| 通信与停止 | 当前网页对活动请求启用默认 3 s 的心跳超时，超时锁止仿真。 | 另行实现设备端超时和现场停止措施，覆盖断网、程序退出、暂停及空闲持物。测量停止响应时间与残余位移。网页心跳不能替代驱动侧故障处理。 |

本项目的仿真、语音识别、网页和取证工具共用 **一个 uv 环境**。设备预约阶段优先使用实验室已验证的驱动环境；若课程控制程序需单独安装，在其目录维护第二个环境，避免改变本项目的依赖锁。第二个环境的版本与启动方式取决于现场课程包，当前仓库没有提供可复现的真机环境锁。[当前依赖声明](../pyproject.toml)

## 2. 场地与机位

| 部位 | 布置要求 | 检查方法 |
| --- | --- | --- |
| 桌面与底座 | 底座刚性固定，标出向前 +X、向左 +Y、向上 +Z。先设置两个可达工位，验证后增加第三个。使用平整、哑光背景。 | 空爪检查完整接近和撤离路径，确认桌沿、相机支架、电缆及人员不在运动范围内；实测工位坐标和台面高度。 |
| 测试物 | 初期采用一个轻型、哑光红色方块，记录边长和质量。仿真方块边长为 24 mm。 | 另拍空桌、工位中心、边缘偏放及同色干扰物。当前颜色检测限定红色，多色选物尚未实现，扩展范围见[系统设计](workflow.md)。 |
| 固定相机 | 用独立支架接近正俯视拍摄，覆盖完整工位、校准标记及夹爪活动区域。固定焦距、分辨率、曝光和照明。 | 用实际镜头决定安装高度；不照搬仿真相机高度。退爪后目标轮廓应完整可见，空爪走一遍路径以确认前臂遮挡区域。 |
| 腕部相机 | 先确认实际设备是否配备摄像头。相机需刚性安装，能看到指尖和撤离后的目标，走线留足活动余量。 | 检查接近、试抬、撤离时的遮挡、裁切和焦点。作为自动复核视角前，需要相机内参、相对腕端的变换及图像与关节位姿的时间对应关系；未完成时只作辅助观察。 |
| 独立测量 | 备直尺、角度尺、已知格距的标定板；侧面设置可看清离桌高度的刻度或见证相机。 | 位移和抓放结果由独立测量核验，不能只引用控制器自己计算的末端位置。 |
| 控制电脑与远端 | 电脑在设备旁连接机械臂及摄像头；先本机验证，再测试局域网。 | 远程浏览器麦克风需可信地址或 HTTPS，也可上传音频。利用两端可见的同一事件测画面延迟，记录丢帧和断连结果。 |

固定相机应完成镜头内参、畸变及工位几何标定。对于固定相机和等高的静置方块，可用分布于工位周围的已知点标定顶面平面映射，并保留未参与标定的中心、边缘点测量 XY 误差。桌面标记与木块顶面存在高度差，必须补偿或采用等高标记；木块被抬起后不能继续使用静置顶面的平面映射。相机、底座、分辨率或物块尺寸发生变化时重新核验。具体标定流程可参考 [OpenCV 官方教程](https://docs.opencv.org/4.8.0/dc/d43/tutorial_camera_calibration_square_chess.html)。

## 3. 有限预约时间内的验证安排

建议按“两天准备与验证，必要时第三天修正”组织。预约前完成软件、记录表及适配器的离线检查；首次现场预留约 90 分钟。以下为待执行计划，不计入已有实验成绩。后一步以先前检查通过为条件，时间不足时保留待测项。

| 时段 | 实验内容 | 验收依据 |
| --- | --- | --- |
| 预约前 | 确认设备资料、校准文件、相机及驱动；准备记录表、标定板与量具。使用已保存的 JSON 检查适配器动作顺序及单位。 | 离线日志能对应每步目标；驱动写入入口、停止行为及异常返回明确。 |
| 0–20 分钟 | 固定底座与机位；记录 COM、校准 ID、相机索引和分辨率；拍空桌、中心、边缘与干扰物。 | 标定误差及检测误差不会把目标判断到错误工位。无法满足时保持观察模式。 |
| 20–35 分钟 | 核对静止反馈的刷新、关节符号和 TCP；按现场流程验证空爪小幅正负运动、本地暂停及空爪断连。 | 保存停止请求与实际停住时刻、残余位移。方向、净空或停止行为未确认时不进行远程连续动作。 |
| 35–55 分钟 | 独立测量 X/Y/Z 各 10 mm 平移及腕部 +3°、−3°、+5°。先用明确文字，再接入获准的语音。 | 同时记录原话、转写、JSON、实际三轴位移/角度与回执，区分语言错误和执行误差。 |
| 55–80 分钟 | 夹持反馈及故障处置验证后，从低位、有支撑的单次抓放开始，再检查工位遮挡和边缘偏放。 | 物体确实随爪抬离桌面，释放后夹爪退开且物体稳定落位。报警、滑脱或反馈不足时终止该回合，保留失败证据。 |
| 80–90 分钟 | 保存日志和视频，记录完成、失败与未测项，按课程流程交接设备。 | 一段完整回合具有指令、软件回执及真实响应的对应记录。未接入网页的课程键盘操作单独标注。 |

现场记录表含 9 次搬运、3 次平移、3 次转腕。计分器按三维位移误差 ≤5 mm、腕角误差 ≤2° 统计运动达标情况；这些是课程实验判分线，不是机械臂精度承诺或安全限值。搬运由现场记录实际落点，并统计“程序报成功但实际未完成”的误报。[计分实现](../arm_lab/field_acceptance.py) · [空白记录表](../results/safety/field_trials_blank.csv)

第三天只针对首次暴露的问题复测，例如边缘定位误差、方向词误识别或夹持停止判据。沿用相同数据口径，另留未用于调参的摆位；语音、视觉、JSON 与物理成功分别统计。

## 4. 现场取证与计分命令

以下命令在本仓库根目录的 PowerShell 中运行。相机索引由现场操作者确认，示例 `0` 和 `1` 不是固定设备编号。工具不会扫描或选择其他摄像头；生成记录表和拍照均不调用模型、不发送机械臂动作。

```powershell
uv sync --frozen --extra voice --extra data
uv run --frozen --extra voice --extra data python -m arm_lab.field_acceptance template outputs/field/trials.csv

# 初始状态：固定视角
uv run --frozen --extra voice --extra data python -m arm_lab.field_cameras --fixed-device 0 --trial 1 --phase before --samples 3 --fps 3

# 释放并退爪后：仅在已确认有腕部相机时加入 --wrist-device
uv run --frozen --extra voice --extra data python -m arm_lab.field_cameras --fixed-device 0 --wrist-device 1 --trial 1 --phase after --samples 3 --fps 3

# 人工填写实际落点、独立测量值及 evidence 路径后计分
uv run --frozen --extra voice --extra data python -m arm_lab.field_acceptance score outputs/field/trials.csv --out outputs/field/score.json
```

取证默认使用 DirectShow，驱动不兼容时可指定 `--backend msmf`。没有腕部相机时省略对应参数；需要动作中画面时使用 `--phase during`。默认输出为 `outputs/field-camera/<回合号>/<阶段>/capture.json` 及 JPEG，报告保留时间、图像哈希、设备信息和失败原因。已有目录不覆盖，重测应使用新的 `--out`。记录表已有测量时也不会被模板命令覆盖。

已有录像可用 `--fixed-video`、`--wrist-video` 代替设备参数。先由共同可见事件确定两路起点，再分别传入 `--start-s` 和 `--wrist-start-s`。报告的 `grab_skew_ms` 仅是本机两次抓帧调用结束时间差，不表示曝光同步或网络延迟。当前取证工具通过了本地仿真录像回放测试，尚无真实摄像头采集成绩。[取证代码](../arm_lab/field_cameras.py) · [录像回放记录](../results/safety/field_camera_replay/01/during/capture.json)

## 5. 本次保留的边界与后续工作

| 本次保留的范围 | 后续需要补充的证据或实现 |
| --- | --- |
| 固定底座、限定工位、单个红色方块 | 其他颜色、尺寸和多目标选择需要同步修改视觉、对象标识与规划校验，并独立评测。 |
| 仿真接触及碰撞检查 | 双侧指尖接触、物体离桌状态和仿真力矩上限不能直接映射为现有真机位置读数或寄存器数值。需要独立画面或经验证的传感反馈。 |
| 报警后终止任务，由现场人员处理 | 不实现自动清除报警、盲目重复闭合或自动重新抓取。故障恢复必须结合实际驱动及托稳、释放程序设计。 |
| 已登记静态障碍的路径预检 | 当前未实现任意动态障碍感知，也不能宣称真机不会碰撞。实体模型误差、线缆和未登记物体需要现场验证。 |
| 固定相机优先，腕部辅助 | 腕部硬件、标定、可见区域和时间同步未确认前，不作为独立的自动完成判据。 |

公开实机轨迹的离线分析也说明，仅凭“夹爪开度低、稳定、能跟随命令”不能证明抓取成功：128 条轨迹中有 123 条在开场即满足该位置窗口条件。该结果不等于 123 次抓取失败，而是说明位置规则缺少判断接触与举起的证据。[轨迹审查记录](../results/safety/real_jaw_evidence.json)

如果首次预约仍无法验证夹持与故障处置，现场目标应限定为空爪位移、图像标定及停止验证，抓放效果继续以仿真结果报告。完整课程驱动核查、原机位说明和早期预约计划保存在[历史文档](archive/hardware_handoff.md)、[驱动核查记录](archive/real_commissioning.md)与[取证说明](archive/field_cameras.md)。
