# 100 条控制输入的提示词对照方法

校方模型的实际调用、留出对照、控制校验及 MuJoCo 重放结果已经汇总。[完整实验报告](planner100_results.md)

本轮要测的是交大 DeepSeek 直接生成控制 JSON 的能力。主指标要求原始回复是完整的单个 JSON，符合控制协议，动作、目标、顺序、轴向、符号和量值与标注相符。单步动作也必须放在 `steps` 数组里。问句须返回含 `action=ask`、`question` 的对象。词表判断问句是否问到了标注的问题，另做定性复核。生产端可以兼容的格式、拒绝的错误计划、实际仿真效果另行统计。

100 条均为本轮自拟的文本及场景摘要。开发集 40 条（28 个动作、8 个规划追问、4 个本地口令），留出集 60 条（42、12、6）。每组的本地口令直接过控制端，不调用模型。所有输入、初态、金标和分组先冻结，API 只发送提示词和本例的 command、objects 及适用的 holding/dialogue。源文件 SHA-256 为 `79d77367c2f22e61fc943b1b09e8ca120f1ab03ee6529be84c915e314bcdd9c3`。[原始输入与金标](../configs/planner100.json) · [输入构造审查](planner100_cases.md)

**配对与选择。** 在开发集比较原提示词与首轮改写。根据开发错误再写一版，在同一开发集复测。优先选择语义及协议都正确的开发回复多、错误运动少的版本，同等时优先保留较短版本。锁定所选版本和原版后，在 54 条相同留出规划输入上成对运行；交错两版发送次序。各版对同一输入只取一次有效 HTTP 回复。抽样没有测量同一提示词多次采样的随机波动。锁版后不再利用留出表现修改同轮候选。[首轮改写](../configs/planner100_candidate.txt) · [开发集修订](../configs/planner100_revised.txt)

**计分。** 严格相等比较解析后的字段和值。语义评分还接受同物体、相同起讫的相邻 pick + place 与 transfer 等价，保留动作顺序。错方向、丢单位、附加平移、错取物工位、多执行一步都不能算正确。问句与参考文本逐字相等只作辅助指标。HTTP 200 的截断或非法 JSON 计为已答但不正确，网络错误、无回复和未测另计。成对差异只用两个版本都拿到回复的输入，另保存每个版本的缺失数。控制端安全分流使用其自己的 10 条分母。[评分代码](../arm_lab/planner_scoring.py)

**这轮实际删改了什么。** 首次候选用紧凑文字列举七种动作，各举一个独立 JSON 对象。读到原版 19 条、候选 20 条开发回复时，已能复现候选把单步正确动作直接输出成裸对象的现象。开发修订版只保留一个**完整的**单步包裹示例；动作清单换成字段签名，避免模型照抄没有外层的例子。另补两条在开发输入中确实出错的区分，即“相对平移不依赖可见木块”及“抓取起点必须有唯一观测”。三版共用模型、采样条件、160 tokens 上限和场景信息。没有使用留出答案设计修订版。

**留出测试开始前的一次补充迭代。** 修订版在开发 P001 生成了抓取、搬运、放置三步，重复了搬运动作已经包含的操作；在 P004 又把观察坐标编进了额外平移。补充候选改用两个含外层的示例（搬运、平移），写清执行器负责搬运路线，并在换算单位后检查上限。为给留出配对留足配额，这一版仅跑固定种子 27091 抽取的 18 条开发动作和 6 条开发追问。选择挑战原版的提示词时，四版只在这相同的 24 条上排名，优先动作 JSON 语义正确数，其次总正确数，再比较本该不动时给出动作的次数、提示词长度。原版始终作为留出配对的对照，未知留出表现时就保存选择记录。三版各 36、补充候选 24、留出两版各 54，共 240 个有计划的模型回复，另有最多 10 次失败尝试的余量。[补充候选](../configs/planner100_finalist.txt)

**复现与配额。** Windows，uv，校方 deepseek-chat，温度 0，每次最大输出 160 tokens。正式试验累计最多 250 次尝试，含失败和重试。每个请求在发送前落盘，原始模型文本、结束原因和可用的 token 数逐次保存。复跑使用同一日志并跳过已有回复。遇到 429 按 Retry-After 或指数退避，反复限流则保存断点。离线复算不需要 API 密钥。

锁定的挑战者为补充候选。在共同开发面板上，四版正确动作数依次为 10、4、13、13（分母 18），总正确数为 11、10、14、18（分母 24）。新版能否作为仿真默认，还要看留出动作 JSON 正确数是否提高，并对照生产端对错误运动的放行情况。[锁版时间、样本与选择记录](../results/safety/planner100/selection.json)
