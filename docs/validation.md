本组测试覆盖三个工位和一个约 24 mm 的规则木块。自由自然语言经校方模型理解，动作能力受当前场景限制。复测保留了工位内偏离中心 19 mm 时出现的漏抓，系统在抬升时结束后续搬运。真实录音识别质量、校园规划服务的实际输出和真机夹持精度需分别验证。

## 首版基线

2026 年 11 月 25 日在当前工程的 uv 锁定环境中执行。表中采用输入文本、本地规则、固定 RGB 相机和 MuJoCo 接触动力学。模型联调使用独立授权，以下数据来自无 AI 调用的基线。

| 用例 | 实际结果 | 独立检查 |
| --- | --- | --- |
| 红块从 A 放到 C | 成功 | 抬升 33.12 mm。两块接触垫均接触木块，抬升时木块已离开桌面。最终只接触桌面，完整处于 C 内。 |
| 同一句口令，红块从 B 放到 C | 成功 | 抬升 33.20 mm。相机选择 B，物理接触及落位均通过。 |
| 向前移动 50 mm | 成功 | 仿真步进后的三轴位移为 [49.991, 0.062, −0.296] mm。三维目标误差 0.303 mm。 |
| 手腕向下 5° | 成功 | 腕关节实际变化 5.006°，误差 0.006°。 |
| 空画面、工位外、含糊口令 | 均请求澄清 | 动作前后关节读数相同。 |
| 红块已经在 C | 回报已完成 | 保持原位。 |
| 要求前进 50 cm | 拒绝 | 超过单次 50 mm 上限，保持原位。 |
| 从 A 中心向负 Y 偏 19 mm | **漏抓，回报未确认** | 工位判定仍为 A，木块抬升 0.00 mm，未形成双侧夹持，最终不在 C 区。 |

10 个用例均得到预期行为。这包含两个正常摆位的成功抓放、一个实测漏抓以及正常的澄清或拒绝。它们的分母、用途不同，不宜合并为“抓取成功率 100%”。独立验收只在测试记录器中读取物体旋转、位置和接触，核对完整木块都在 C 内，并在夹爪退开后的三次采样中仅接触桌面。业务规划只读取 RGB 检测结果和工位表。[逐回合记录](../results/preliminary/report.json)

## 实际遇到的问题

- 初始预备姿态的末端偏低。向下转 5° 触发了桌面净空保护。将预备姿态抬高后重跑，测得上述腕角。保护阈值保持不变。
- 在高度 102 mm 的垂直进爪姿态，某些工位所需腕角超过模型上限。采用验证可达的 82 mm 搬运高度并重新布置 C 工位。
- 固定取料位不能保证格内任意位置都能夹起。19 mm 偏置故意复现了这一局限。进一步改善应优先考虑按像素中心修正夹持点，或缩小允许放料区域。
- 本次物理模型以两个近似接触垫计算抓握，木块仅在重置时设置位置，其后由自由关节积分。没有将木块焊接到夹爪。室内噪声、USB 延迟、实物摩擦和机器人关节标定仍需独立测试。

## 首版工程验证

切换至交大 DeepSeek 后，12 项 unittest 通过。其中两条固定 A/B 口令使用本地生成的 HTTP 回包，验证请求的接收方、参数、输入内容以及仿真搬运。错误起点的回包会在关节变化前被拒绝。缺少 Key、旧配置指向其他网关、截断回包、重定向及 HTTP 401/429 均有覆盖。再次运行原有 10 个规则仿真用例，全部得到预期结果，包括 19 mm 偏置时的漏抓。[接口测试](../tests/test_deepseek.py)

另以独立的 Windows Edge 会话打开本机服务，切换 B，实际点击执行 B→C、平移及模糊口令，再复位至 A。浏览器测试未记录前端脚本错误。[控制台截图](../results/control_panel.png)

[10.67 秒的单相机 H.264 录像](../results/pick_B_sim.mp4)记录 B→C 的实际仿真步进。录像中的文字口令使用规则解析。此文件可作为前期仿真材料，实机课程演示另行录制。
