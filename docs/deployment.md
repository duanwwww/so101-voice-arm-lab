~~~mermaid

    U -->|"手输原话或澄清答复"| T
    V["OpenCV 固定相机"] -->|"可见木块、工位、底座 XY"| L["上海交大 DeepSeek"]
    T --> K["控制端判断整句含义"]
    K -->|"动作请求与澄清答复"| L
~~~

1. **输入。** 录音或上传经 SenseVoiceSmall INT8 转成中文，操作者可编辑转写后提交。手输和转写进入同一个规划接口。
2. **规划。** 控制端先判断提交的整句。禁止、暂停、恢复及询问进度直接在本机处理。其余任务选择交大 deepseek-chat 并获批后，控制端发送原话和 RGB 提取的物体、工位及坐标摘要。有明确回复关系时还附上上一轮问题和指令。模型返回澄清问题或至多四步动作的 JSON。也可选择本地规则。[校方模型说明](https://apps.hpc.sjtu.edu.cn/posts/claw-guide-sjtu-api)
3. **视觉。** OpenCV 用 HSV 及连通域提取红块。像素中心通过相机内外参与已知木块顶面求交，得到底座 XY 毫米坐标。外接框完整落入 A/B/C 中的一个工位才给出标签。桌面前方为底座 +X，左侧为 +Y，向上为 +Z。A 在画面左方，B 在右方，C 在前方中间。木块被抬起时，控制端传递指尖夹持状态，并停用台面投影。
4. **执行。** 原子动作包括抓起并持有、放到目标工位、搬运、定量平移、腕部俯仰、观察和归位。动作执行前检查整条序列。每个后续动作使用新的观测重新检查前提。若中途接触丢失、IK 不可达或位置复核未通过，回执记录实际完成的步骤并结束该次序列。
5. **结果反馈。** 系统保留执行器的原始回执。选择语音反馈时，DeepSeek 可再读入本次指令、步骤、状态和放置后的工位，生成中文解读。Edge-TTS 合成原始回执和获批的解读。反馈端的数据出口只能生成文字或音频。

2026 年 11 月 26 日起，抓取前重新拍图，在限定范围内微调夹爪中心，试抬确认后才开始正式搬运。动作逐段预检臂段运动和持物外形。软件停止、反馈无效和失去夹持的处置，以及腕部复核的条件见[控制实验报告](control_iteration.md)。

例如，摄像头看到木块在 B，操作者说“让面前的积木去左边，随后把手腕往上抬两度”。一种合法规划如下。

~~~json
{"steps":[{"action":"transfer","object":"red_1","from":"B","to":"A"},{"action":"wrist","deg":-2}]}
~~~

第一步展开为抓取、放置和相机复核。第二步测量转腕实际值。若录音只有“把前面的木块抓起来”，对应动作是 pick，抓取后保持夹持，下一句可单独指定放置位置。

## 接口

| 接口 | 输入与结果 |
| --- | --- |
| GET /api/scenarios | 返回可切换场景的编号、中文名称、摆设说明和可编辑的示例任务。 |
| GET /api/state、GET /camera.jpg | 状态含场景版本、最新观测、夹持状态、busy、paused、stopped、最近回执与批准方式。相机端点独立返回 JPEG。 |
| GET /camera/wrist.jpg | 刚性安装在仿真夹爪上的相机视图。 |
| POST /api/stop | 在 HTTP 线程设置停止事件，运动线程在控制周期消费并锁住新动作。仿真手动重置后恢复。 |
| POST /api/heartbeat | 当前发指令的页面刷新状态并成功解码所选相机的一张 JPEG 后发送。在 JSON 中提供指令 id 和这条指令专用的 watchdog_token。控制电脑按单调时钟计时，默认期限 3 秒。 |
| POST /api/transcribe | 音频文件。返回可编辑的中文转写。 |
| POST /api/command-kind | 提交 `{"text":"不要向前移一厘米"}` 得到 `{"kind":"ignore"}`。只检查文字，不改变状态或调用模型，供网页决定是否显示模型授权。 |
| POST /api/commands | UUID、文字、场景版本、发出时间及可选的 use_deepseek。回复追问附上 reply_to。服务端独立复核文字类别。进行中可提交禁止、暂停或状态查询。新运动忙时返回 409；旧画面版本和过期答复也会被拒绝。 |
| POST /api/feedback?receipt_id=… | 根据指定的当前回执请求校方模型解读，保存到该回执。 |
| POST /api/speak?receipt_id=… | 播报当前选定的回执。 |
| POST /api/reset | 输入上表场景目录中的 layout 编号。重新布置木块、视觉道具、遮挡与相机增益。GET /api/state 的 layout 返回当前生效场景。 |

本机浏览器上的单次确认只适用于该请求。局域网远端页面使用控制电脑预先批准的预算。SenseVoiceSmall 在 Windows 控制端运行，校方 DeepSeek 与微软 TTS 通过各自网络服务运行。工程安装、权重路径及接入方法见 [README](../README.md)。

远程 API 客户端提交运动请求时生成两个不同的 UUID，分别为 id 和 watchdog_token。只有该对标识可以续期。关页、所选相机解码失败或状态请求失败会停止续期。规划或动作执行中的监控超时会锁止控制，必须在任务退出后手动重置。旧版本机客户端支持省略 watchdog_token，当前网页在本机和远端均为运动请求启用心跳。

### 任务进行中的交互

| 提交的整句 | 当前任务和场地如何变化 |
| --- | --- |
| “不要向前移一厘米”或“不要暂停” | 返回 ignored。已有任务按原计划继续。禁止句本身不会送给模型，也不会启动动作。 |
| “现在在做什么” | 返回 observed 及最近一次夹持反馈。忙时的查询或禁止回执单独返回给调用方，活动任务的版本、最新执行回执和心跳所有权保持原状。 |
| “暂停当前任务” | 控制端立即设置暂停标志。进行中的动作在下一次检查时取消剩余步骤，迟到的规划结果会被丢弃。暂停口令的回复表示信号已送达，原任务的最终回执才记录实际完成到哪一步。 |
| “恢复控制” | 等原任务返回后，再核对现场、明确提交。恢复不会移动物体或重放旧计划。重新提交的新动作根据当前姿态、夹爪和场地执行。悬空持物需双侧夹持反馈有效；部分接触或离桌情况不明时继续保持暂停。急停和故障锁止需要手动重置。 |
| 动作未结束时说出下一条运动 | 可以录音、转写、编辑，也可随时查询进度或暂停。运动草稿保留在输入框，操作人核对新画面后再提交。服务端不会排队执行这一草稿。 |

本地交互按完整话句处理。语音须先结束录音、经本机 SenseVoiceSmall 识别，再由操作者提交。网页“暂停当前任务”和“停止仿真运动”可直接发信号，无需等待录音或模型。每次提交使用独立 id 和当前 revision。在最近 128 条回执的缓存内，相同 id 与内容重试只返回原回执，调整过版本的旧恢复请求不能解除下一次暂停。

**暂停后的监控边界。** 监控超时计时只覆盖当前请求的规划和执行。原任务尚未退出时，断图或掉线仍可触发硬锁止；原任务回执返回后心跳结束，即使夹爪仍持物也没有空闲失联报警。此时 MuJoCo 没有后台物理步进，墙钟前进不会改变场内位姿或模拟时间。已确认夹住并离桌时，位置闭合保持禁用，握持力矩继续限幅；已连接客户端仍可触发硬停止，恢复口令不能解除。真实设备会受重力、发热、打滑和驱动失联影响，空闲持物需要独立的本地反馈及断连处置，不能套用这个冻结的仿真结果。[进行中交互与暂停测试](../tests/test_live_interaction.py) · [失联测试](../tests/test_watchdog.py)
